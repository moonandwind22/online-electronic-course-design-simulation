# 在线电子课设仿真平台 · 实施计划

> 仓库：`moonandwind22/online-electronic-course-design-simulation`（当前分支 `trae/agent-bKAPh7`）
> 目标：一个可直接在浏览器运行的电子课程设计仿真平台，覆盖数电、模电、电力电子、51 单片机、STM32 单片机五大方向。

---

## 1. 目标与验收口径

### 1.1 产品目标

构建一个中文、离线可用、无需后端的单页 Web 应用：

1. **统一原理图编辑器**：拖放器件、正交布线、旋转/镜像、网络标签、缩放平移、撤销重做、自动保存。
2. **五个仿真域**：数电、模电、电力电子、51 单片机、STM32 单片机；共享编辑器与器件面板，每个工程属于一个仿真域。
3. **丰富器件库**：
   - 数电 ≥ 55 种 IC（74LS 为主，含 74HC595、CD4000 系列；下方清单为 70+ 项目标，按批次交付，最低 55 种）+ ≥ 18 种数字外设；
   - 模电 ≥ 26 种器件 + 示波器/万用表/信号源等仪器；
   - 电力电子 ≥ 14 种功率器件/源 + 5 个典型拓扑模板；
   - 51 最小系统板 + STM32F103C8T6 最小系统板。
4. **固件在线烧录**：51 与 STM32 均支持上传 Intel HEX、校验、烧录进度、复位运行、寄存器/SFR 监视、串口终端。
5. **一键 AI 网表**：工具栏一键生成 AI 可读的“接法文法”（紧凑文本 / 自然语言 / JSON），一键复制/下载，包含器件、引脚号、网络、电源、MCU 固件与引脚映射、仿真快照、检查告警。
6. **示例工程**：每个仿真域 3–5 个可运行模板，打开即用。

### 1.2 验收标准（Definition of Done）

- `npm run build`、`npm run typecheck`、`npm test` 全部通过。
- 每个仿真域至少一个端到端示例可在浏览器中运行并产生可见结果：
  - 数电：74LS161 + 74LS47 + 数码管计数；
  - 模电：RC 低通阶跃响应与共射放大电路工作点；
  - 电力电子：Buck 电路 12 V → 约 5 V（50% 占空比）；
  - 51：上传 `blink51.hex` 后 P1.0 LED 闪烁；定时器中断与 UART 输出正常；
  - STM32：上传 `blink_stm32.hex` 后 PC13 LED 闪烁；UART 打印正常。
- AI 网表弹窗可一键复制，文本包含全部器件、引脚号/引脚名、网络、MCU 固件信息与检查结果。
- 120 个数字器件规模下仿真交互保持流畅（≥ 30 fps UI，逻辑事件不丢帧）。
- 桌面 1440×900 为主视口，1024 宽可用，768 宽降级为抽屉式面板且不横向溢出。

## 4. 关键决策与假设

| # | 决策 | 理由 / 影响 |
| --- | --- | --- |
| D1 | **静态 SPA，无后端、无账号**；工程存 localStorage，支持 JSON 导入导出 | 部署简单、离线可用；不做云同步与协作 |
| D2 | **五个仿真域 = 五类工程**，共享编辑器；一个工程只属于一个域 | 避免全混合信号求解器的复杂度；切换域时新建/打开对应工程 |
| D3 | **原理图级**，不做面包板/PCB/走线寄生 | 用户诉求是“连成的图”和课设验证，原理图足够 |
| D4 | 数电引擎 **自研事件驱动**，四态 + 三态 + 开集/弱上拉 | 55 种 74LS 需要可控的器件建模与高事件吞吐 |
| D5 | 模电/电力电子采用 **brownout 0.7.0**（MIT，MNA/SPICE 子集，浏览器可用）作为求解内核，包在 `AnalogAdapter` 后 | 获得收敛处理、BJT/MOS/运放/555/变压器等成熟模型；避免自研 SPICE 的收敛风险 |
| D6 | 51 采用 **自研 TS 内核**（完整 MCS-51 指令集 + SFR/定时器/串口/中断/准双向口） | 需要位级端口模型与教学可控性；无合适现成浏览器库 |
| D7 | STM32 采用 **stm32f1-emu 3.3.0**（MIT，Rust→WASM，STM32F103 全系统）包在 `Stm32Adapter` 后 | 支持真实 HEX 固件与 GPIO 事件，自研 Cortex-M3 风险过高 |
| D8 | 固件只接受 **Intel HEX**；不内嵌 C 编译器 | 与 Keil/SDCC/STM32CubeIDE 工作流衔接；避免浏览器内工具链 |
| D9 | **AI 网表为本地文本生成**，不调用任何 AI API | 一键复制即可交给任意 AI 排查；无密钥、无网络依赖 |
| D10 | 高频 PWM 的 MCU↔模拟联合仿真**不做**；电力电子模板使用内置 PWM 源，MCU 引脚可用于低速使能/开关控制 | 避免每帧重建模拟矩阵；把范围锁在可交付质量内 |
| D11 | UI 全中文，深色“实验室工作台”为默认主题，提供浅色主题 | 长时间调试舒适；课堂投影对比度足够 |
| D12 | 桌面优先，1024 可用，768 抽屉式降级 | 课程设计主要在电脑完成 |
| D13 | 依赖全部固定小版本并提交 lockfile；brownout 与 stm32f1-emu 均做 **Phase 0 Spike 验证** | 两者均为较新的第三方包，必须先在 Vite 生产构建中验证 |

**明确不做（Out of Scope）**：PCB 布局/走线、面包板视图、SPICE 签核级精度、三相电机矢量控制、RTOS 调试、云端工程、多人协作、浏览器内 C 编译、模拟域任意高速数字联合仿真。

## 7. 核心设计

### 7.1 数据模型与网络提取

```ts
type Domain = 'digital' | 'analog' | 'power' | 'mcs51' | 'stm32';

interface CircuitDoc {
  id: string; name: string; domain: Domain;
  components: Component[]; wires: Wire[];
  viewport: { x: number; y: number; zoom: number };
  createdAt: number; updatedAt: number;
}

interface Component {
  id: string; type: string;          // PartDef.type
  x: number; y: number;
  rot: 0 | 90 | 180 | 270; mirror: boolean;
  label: string;                     // U1 / R1 / LED1
  params: Record<string, number | string>;
  state?: Record<string, unknown>;   // 开关、电位器、按键等交互状态
}

interface Wire { id: string; points: Point[]; from?: PinRef; to?: PinRef; netLabel?: string; }
```

- **网络提取**：并查集合并 `Wire.from/to` 与导线端点重合的引脚；生成 `Net { id, name, pins[] }`。
- **命名优先级**：用户网络标签 > 电源符号（VCC/GND/3V3/5V）> 自动 `N1..Nn`；排序稳定，保证 AI 导出可复现。
- **导线**：正交折线（水平/垂直），拖动端点吸附引脚；三线以上交汇绘制结点；悬空端点标红。
- **撤销/重做**：文档快照栈（上限 50），对拖动进行合并（同一次手势一个快照）。

### 7.2 原理图编辑器

- SVG 画布：`viewBox` 缩放，10 px 栅格，点阵背景；支持滚轮缩放、空格拖拽平移、框选、多选移动。
- 交互：`R` 旋转、`X` 镜像、`Delete` 删除、`Esc` 取消、`Ctrl/Cmd+Z/Y` 撤销重做、`F` 适配视图。
- 引脚：悬停显示名称/编号；连接到网络时高亮；点击网络在检查器中显示当前逻辑/电压。
- 仿真可视化：
  - 数电：高电平网络青色，低电平灰色，高阻虚线，冲突网络红色脉冲；
  - 模拟：可选“电压热力”着色（0V 蓝 → VCC 红），默认关闭；
  - 外设：LED 发光、数码管段亮、LCD 文本、电机转动、舵机角度、蜂鸣器动画。
- 画布只重绘动态层（`sim` store 以 30 fps 推送快照），静态符号用 `React.memo` 避免全量重渲染。

### 7.4 数电引擎

- **事件驱动**：每个器件模型实现 `eval(inputs, state) -> { outputs, nextState, delay }`；输入变化入优先队列，按逻辑延迟推进；单帧事件预算（默认 200k）防止死循环。
- **网络仲裁**：强驱动 0/1、弱上拉/下拉、开集/开漏、三态；冲突 → `X` 并记录告警。
- **时序器件**：上升沿触发；异步清零/置位优先；计数器/移位寄存器严格按数据手册功能表实现。
- **时钟/脉冲源**：以逻辑事件注入，支持频率 0.1 Hz–10 MHz（高频率配合“最大速度”模式）。
- **LED/数码管/LCD**：读取网络电平渲染；LCD1602 实现 HD44780 初始化、清屏、光标、写字符、4 位模式半字节时序。
- **逻辑分析仪**：用户选择最多 8 个网络，环形缓冲采样，底部波形面板显示。

### 7.5 模电 / 电力电子引擎（brownout 适配）

- `AnalogAdapter` 职责：
  1. `CircuitDoc → brownout SimCircuit`：器件 `kind`、引脚 `id`、参数单位映射；同一网络的引脚按链式 `wires` 连接；确保存在参考地。
  2. 生命周期：`load()`（拓扑变化/开关/电位器调整时重建，brownout 按组件 ID 保留电容电压与电感电流）、`step(dt)`、`coldLoad()`（复位）。
  3. 采样：每步读取 `netV`，按时间窗抽取到示波器环形缓冲；探针读取瞬时值。
  4. 失败/告警：映射为中文提示（不收敛、悬空节点、电源短路等），显示在状态栏与“检查”面板。
- **时间步**：按模板预设 `dt`（模电 20–50 µs；电力电子 0.5–2 µs），支持 0.1×/0.5×/1×/最大 速度；每帧步数上限（默认 2000）保证 UI 响应。
- **仪器**：
  - 示波器：2 通道、时基/幅值/触发（上升/下降/自动）、游标、Vpp/Vavg/Vrms/频率/占空比测量；
  - 万用表：DC/AC 电压、电流、电阻（对未上电电路做等效电阻近似需谨慎，首版只做电压/电流）；
  - 信号源：正弦/方波/三角/脉冲，频率、幅值、偏置、占空比可调。
- **电力电子**：
  - IGBT = MOSFET + 体二极管 + 饱和压降近似；SCR = 双晶体管锁存子电路；均以组合子电路实现，不修改 brownout 内核；
  - 开关节点自动附加极小 RC snubber 以帮助收敛，并在“检查”中说明；
  - 模板自带推荐时基与测量项（如 Buck 的 Vout_avg、ΔVout、电感电流）。
- **已知边界**：不做器件级寄生/热模型；LED 需串限流电阻（检查项会提示）；高压电路仅作教学演示。

### 7.6 51 单片机引擎（自研）

- **CPU**：完整 MCS-51 指令集（含位操作、`MUL`/`DIV`/`DA`、`MOVC`/`MOVX`、`DJNZ`、`RETI`）；按 12 时钟/机器周期计时；周期表驱动。
- **存储器**：256 B 内部 RAM（含位寻址区）、64 KB 代码空间、128 B SFR。
- **SFR**：P0–P3、PSW、SP、DPL/DPH、TCON、TMOD、TL0/TH0/TL1/TH1、SCON、SBUF、IE、IP、PCON；未实现位读回 0 并告警。
- **定时器**：T0/T1 模式 0/1/2（模式 3 基础支持），溢出置位、中断向量 0x000B/0x001B。
- **串口**：模式 1（8 位 UART），波特率由 Timer1 计算；`SBUF` 写入 → 串口终端输出，终端输入 → `SBUF` 接收并置 RI；支持中断。
- **中断**：INT0/INT1 边沿/电平、T0/T1、串口；两级优先级；压栈/`RETI` 正确。
- **端口模型**：
  - P0 开漏（输出 1 = 高阻，需外部上拉）；
  - P1–P3 准双向（锁存 1 = 弱上拉约 50 kΩ，锁存 0 = 强下拉）；
  - 读引脚 vs 读锁存器语义正确；与数字网络仲裁器共用同一套驱动模型。
- **固件**：Intel HEX 解析（支持 00/01/02/04/05 记录、校验和、地址越界检查）；烧录流程 = 解析 → 校验 → 写入代码空间 → 复位 PC=0；显示固件大小、校验和、入口处反汇编可选（首版显示 PC 与代码字节）。
- **运行**：每帧按机器周期预算推进（默认 20k 周期/帧，1× 实时约 12 MHz/12）；速度档 0.1×/0.5×/1×/最大。
- **调试视图**：寄存器（A/B/DPTR/SP/PC/PSW）、SFR 表、端口锁存与引脚电平、当前中断状态。

### 7.7 STM32 引擎（stm32f1-emu 适配）

- `Stm32Adapter`：
  1. 动态加载 `stm32f1-emu` 与 WASM 资产；`STM32F1.create({ firmware, chip: 'stm32f103c8' })` 或 `fromHex(hexText)`。
  2. 运行预算：每帧 `execute(n)`，默认 1.2 M 指令/帧（72 MHz 实时），最大档 4×；`requestAnimationFrame` 驱动。
  3. GPIO：板卡 `PAx/PBx/PCx` 与网络绑定；MCU 输出变化 → 数字网络驱动；网络电平变化 → `pin.setInput()`；同时把引脚模式/当前电平显示在检查器。
  4. UART：`uartOutput` 增量送入串口终端；终端发送 → `uartRx()`。
  5. 固件：Intel HEX 上传 → 校验 → 重启；显示 Flash 大小与校验和；提供复位、暂停、单步（按指令/按毫秒）。
- **时序**：数字外设（LED、数码管、LCD、按键、舵机、步进电机）由数字网络与 STM32 引脚事件驱动；模拟外设不接入，避免跨域复杂度。
- **已知边界**：仅 STM32F103C8（Blue Pill）型号；ADC/SPI/I2C 由仿真器支持但首版 UI 只暴露 GPIO/UART/NVIC/SysTick/TIM 的可观测状态。

### 7.8 AI 网表“接法文法”

工具栏醒目按钮 **“AI 网表”**（图标 + 文字，快捷键 `Ctrl/Cmd+Shift+A`），打开右侧大抽屉：

- 顶部：格式切换 `紧凑文本`（默认）/ `自然语言` / `JSON`；开关 `包含仿真快照`、`包含检查结果`；按钮 `复制`、`下载 .txt/.json`。
- 正文：等宽字体预览，语法高亮（分段着色），滚动同步。
- 复制：`navigator.clipboard.writeText`，失败回退 `textarea + execCommand`；成功 toast。

### 7.9 检查与告警

在“检查”面板与 AI 网表中统一输出（错误/警告/提示）：

- 电源未接、VCC-GND 短路、无地节点；
- 输入悬空（TTL/CMOS 区分提示）、输出冲突、三态总线无上拉；
- 74LS 电源脚未接（隐藏电源脚统一处理，但会检查）；
- MCU 未烧录固件、引脚未绑定、固件校验失败；
- 模拟：节点无直流通路、缺少参考地、LED 无限流电阻、器件耐压/电流越界（brownout 告警映射）；
- 仿真：不收敛、时间步过大、事件风暴（数字振荡）。

## 9. 实施阶段（按顺序执行）

### Phase 0 · 脚手架与关键技术 Spike（先验证，再铺 UI）

1. 初始化 Vite + React + TS 手写配置（不依赖交互式脚手架）：
   - `package.json` 依赖：`react`、`react-dom`、`zustand`、`clsx`、`lucide-react`、`brownout@0.7.0`、`stm32f1-emu@3.3.0`、`tailwindcss`、`@tailwindcss/vite`、`@fontsource/space-grotesk`、`@fontsource/jetbrains-mono`；dev：`vite`、`@vitejs/plugin-react`、`typescript`、`vitest`、`@types/react`、`@types/react-dom`。
   - `vite.config.ts`：`base: './'`、React 插件、Tailwind 插件、`build.target: 'esnext'`、必要时 `optimizeDeps.exclude: ['brownout']`、`assetsInclude: ['**/*.wasm']`。
2. **Spike A（brownout）**：临时页面构造 RC 阶跃，`step(1e-5)` 后读取 `netV`，验证：
   - `t=1τ` 时输出 ≈ 3.16 V（±2%）；
   - 开关器件参数变化后 `load()` 保留电容电压；
   - 浏览器控制台无 WASM/JSON 导入错误；`vite build` 后仍可运行。
3. **Spike B（stm32f1-emu）**：加载手写 `blink_stm32.hex`，`execute()` 后读取 PC 与 PC13 事件；验证开发与生产构建均能加载 WASM。
4. 若 Spike 失败：
   - brownout → 降级到 `@strategicprojects/dune-sim`（BSD）或内置最小 MNA（仅 R/C/L/源/二极管/开关），并在计划外记录决策；
   - stm32f1-emu → 用 `?url` + 手动 `locateFile` 加载 WASM；仍失败则改用 `stm32f4-emu` 并同步调整板卡型号。
5. 视觉概念（build-web-apps 流程）：生成 1 张主工作台概念图（深色实验室工作台），提取布局比例、面板层次、质感与强调色，落地为 `tokens.css`；界面文案以本计划为准，不采用生成图里的文字。
6. 建立字体、主题、App 外壳（顶栏/三栏/底坞）、Toast、Modal 基础组件。
7. 建立 `types.ts`、`netlist.ts`、`storage.ts`、三个 Zustand store、撤销重做。

**验收**：两个 Spike 页面均通过；`npm run build` 成功；空壳布局在 1440/1024/768 下无溢出。

### Phase 1 · 编辑器与器件注册表

1. 画布：栅格、缩放/平移、拖放、选择/框选、拖动吸附、旋转/镜像、删除、复制粘贴、键盘快捷键。
2. 布线：引脚点击开始/结束，正交折线预览，自动结点，网络标签；非法连接提示。
3. 器件注册表与通用符号：`ChipBox`（DIP 双列）、`Gate`（IEEE 门形）、`Peripheral`（外设）、`Board`（板卡）。
4. 器件面板：分类 Tab（数电/模电/电力电子/51/STM32/外设/仪器）、搜索、最近使用、拖入画布。
5. 检查器：参数编辑（值/单位校验）、引脚表、网络信息、器件说明。
6. 工程管理：新建/重命名/删除、自动保存、JSON 导入导出、模板库骨架。

**验收**：可完成“放置 74LS00 + 两个开关 + LED、连线、保存、刷新恢复”。

### Phase 2 · 数电引擎与外设

1. `digital/engine.ts`：事件队列、时间推进、单帧预算、事件风暴保护。
2. `digital/resolver.ts`：强/弱/三态/开集仲裁与冲突标记。
3. 器件模型分批实现（每批后跑单测）：
   - 批次 1：门/缓冲/三态（19 种）；
   - 批次 2：触发器/锁存器（12 种）；
   - 批次 3：计数器（12 种）；
   - 批次 4：移位寄存器（6 种）+ 译码/编码/选择器（11 种）；
   - 批次 5：运算/比较/定时 + CMOS（13 种，含 NE555）。
4. 外设：LED、数码管、按键、拨动/DIP、蜂鸣器、时钟/脉冲源、逻辑探针、矩阵键盘、LCD1602、继电器、电机、舵机、步进、交通灯。
5. 运行控制：运行/暂停/单步/复位/速度（0.1×/0.5×/1×/最大）；网络着色；引脚悬浮状态。
6. 逻辑分析仪面板（8 通道）。
7. 5 个数电模板 + 单测（74LS161 序列、74LS138 译码、74LS373 锁存、74LS595 移位、74LS85 比较）。

**验收**：74LS161+74LS47+数码管模板运行 0–9 循环；按键/开关交互有效；120 器件仍流畅。

### Phase 3 · AI 网表与检查（数电先闭环）

1. `features/ai/formats.ts`：三种格式生成器；确定性排序；单位格式化。
2. `AiNetlistModal`：格式切换、快照/检查开关、复制、下载、预览高亮。
3. `checks/checks.ts`：电源、悬空、冲突、总线、MCU 固件、模拟专项检查；输出结构化 issue。
4. 顶栏“AI 网表”一键入口 + 快捷键；复制成功 Toast。
5. 快照测试：固定电路 → 三种格式 golden 文本；校验包含引脚号/名、网络、检查项。

**验收**：任意数电工程一键复制，文本可直接交给 AI 并理解；复制/下载在 Chrome 中成功。

### Phase 4 · 模电引擎与仪器

1. `AnalogAdapter` + `mapping.ts`：实现 R/C/L/源/二极管/LED/稳压管/BJT/MOS/运放/比较器/555/稳压器/继电器/开关/电位器/电池/变压器/电机/灯泡/保险丝/热敏/光敏。
2. 器件符号与参数面板（阻值、容值、电压、频率、占空比、模型选择等）。
3. 示波器：2 通道、时基、幅值、触发、游标、自动测量；环形缓冲与抽取。
4. 万用表、探针、节点电压/支路电流显示。
5. 收敛/告警中文映射；仿真状态栏（t、dt、步/秒、求解状态）。
6. 5 个模电模板 + 单测（RC 时间常数、半波整流、共射工作点、运放增益、555 频率）。

**验收**：各模板波形正确；修改电位器/开关后波形连续；不收敛时有可执行提示。

### Phase 5 · 电力电子

1. 功率器件：MOSFET（体二极管）、IGBT（子电路）、SCR（双晶体管锁存）、快速二极管、理想开关、栅极驱动、PWM 源、ESR 电感/电容、三相源、R-L 负载、snubber。
2. 电力电子分类面板与专用仪器预设（Vout_avg、Vrms、纹波、占空比、频率）。
3. 5 个拓扑模板（半波、桥式整流、Buck、Boost、全桥逆变）。
4. 性能档：1 µs/0.5 µs 步长、每帧步数预算、仿真速度档。
5. 单测：Buck 12 V/50% → 5 V ±5%；Boost 5 V/50% → 约 9.5 V；桥式整流 Vavg ≈ 0.9 Vin。

**验收**：模板打开即出稳定波形；示波器测量值与理论值在 ±5% 内；界面不卡顿。

### Phase 6 · 51 单片机

1. `mcs51/cpu.ts`：指令译码执行 + 周期表；`sfr.ts` 内存映射。
2. `timers.ts`、`uart.ts`、`ports.ts`（P0 开漏/准双向）、中断控制器。
3. `hex.ts`：Intel HEX 解析、校验、扩展地址。
4. 板卡器件 + 固件面板（上传、校验、烧录进度、复位/运行/暂停/单步、速度档）。
5. 调试视图：寄存器、SFR、端口锁存/引脚、中断标志；串口终端收发。
6. 外设联动：LED、数码管、按键、矩阵键盘、LCD1602、蜂鸣器、步进电机。

8. 浏览器端到端：上传 `blink51.hex` → P1.0 闪烁；`uart51.hex` → 终端输出“Hello 8051”。

**验收**：HEX 上传/校验/复位/运行完整闭环；LCD1602 与矩阵键盘示例可用。

### Phase 7 · STM32 单片机

1. `Stm32Adapter`：动态导入、WASM 初始化、`fromHex`、运行预算、暂停/复位、销毁。
2. GPIO 绑定：PA/PB/PC 与网络双向同步；引脚模式/电平显示。
3. UART：输出缓冲 → 终端；终端发送 → `uartRx`。
4. Blue Pill 板卡符号（左右各 20 脚，标注复用功能）、固件面板、PC/寄存器/SysTick 视图。

6. 速度档与指令预算；异常（固件非法、WASM 加载失败）中文提示与重试。

**验收**：上传 HEX 后 3 秒内可见 PC13 闪烁；串口输出正确；刷新页面后固件与电路恢复（固件内容存 localStorage，体积上限 256 KB）。

### Phase 8 · 整合、视觉与 QA

## 11. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| brownout 0.7.0 较新、API 可能变化 | 模拟引擎集成失败 | 固定版本；`AnalogAdapter` 隔离；Phase 0 Spike；失败则切 `dune-sim` 或内置最小 MNA |
| stm32f1-emu WASM 在 Vite 生产中加载失败 | STM32 无法运行 | Phase 0 Spike；`?url`/`assetsInclude`/手动 `locateFile`；必要时改 `stm32f4-emu` |
| 55 种 74LS 建模工作量大 | 进度/正确性 | 表驱动 + 共享基类 + 分批单测；每批可独立验收 |
| 8051 指令集边界情况 | 固件运行异常 | 完整 ISA + 周期表；用已知机器码单测；寄存器/SFR 可视化便于定位 |
| LCD1602 时序/4 位模式复杂 | 外设不显示 | 简化 HD44780 但严格处理初始化序列；先支持 8 位，再补 4 位 |
| 电力电子收敛困难 | 波形错误/报错 | snubber、ESR、步长档、brownout 告警中文映射与建议 |
| 模拟求解阻塞 UI | 卡顿 | 每帧步数预算 + 速度档；后续可迁移 Web Worker |
| 第三方许可 | 合规 | 仓库 GPL-3.0；brownout/stm32f1-emu 均 MIT；关于页列第三方许可 |
| 剪贴板权限 | 复制失败 | `navigator.clipboard` + `execCommand` 回退 + 手动全选提示 |
| 固件体积/持久化 | localStorage 超限 | 单固件上限 256 KB；超限提示仅本次会话有效 |
